### 이벤트 기반 사진 공유 · 5주차 워킹 프로토타입

**흩어진 사진을 모으고, AI 추천을 비교하며, 공유할 사진은 사용자가 결정합니다.**

여행·모임·행사의 사진 찾기와 선별 부담을 줄이는 모바일 웹 PoC입니다. 사용자경험디자인 II 과제로 **Figma Make → Claude → Codex**를 이어서 사용하며 제작했습니다.

| :--- | :--- | :--- |
| 단일 HTML 프로토타입 | GitHub 업로드·배포 완료 | 2026.10.10 |

> **현재 범위:** 화면·선택·탐색 동작을 구현했습니다. 실제 AI 분석·기기 사진 검색·저장·SNS 공유는 시연 단계입니다.

## 실행 방법

1. 프로젝트 파일을 내려받습니다.
2. `phou-prototype-15_1010 마지막.html`을 브라우저에서 엽니다.
3. 홈의 `+`로 앨범을 만들거나 기존 앨범 카드를 누릅니다.

| 항목 | 안내 |
| :--- | :--- |
| 설치·빌드 | 필요 없음 |
| 인터넷 | 외부 샘플 사진을 불러올 때 필요 |
| 상태 확인 | 데스크톱 왼쪽 위 메뉴에서 로딩·빈 상태·접근 거부 선택 |
| GitHub 주소 | **업로드 후 입력 예정** |
| 배포 주소 | **배포 후 입력 예정** |

작은 화면에서는 상태 선택 메뉴가 숨겨집니다. 접근 거부는 실제 기기 권한 조회가 아닌 시연 상태입니다.

## 프롬프트 설계

### 01. 초기 지시를 구체적으로 작성

| 지시 영역 | 구체적으로 전달한 내용 |
| :--- | :--- |
| 목적·대상 | 이벤트 사진 공유 / 보내는 사람 / 20~30대 |
| 입력 자료 | 손그림은 레이아웃, 레퍼런스는 색·형태·분위기 |
| 화면 범위 | 홈 → 생성 → 옵션 → 사진 확인 → 링크·QR의 5개 화면 |
| 디자인 | 흑백 색상 코드, pill 버튼, 모서리, 폰트, 여백, 아이콘 |
| 상호작용 | 이름 입력 전 비활성, 사진 선택·장수 변경, 화면 연결 |
| 상태 | 로딩·빈 상태·사진 접근 거부 |
| 제외 범위 | 로그인·보정·받는 사람 등 첫 구현에서 만들지 않을 기능 |

**아래는 제공된 Claude 대화에 남아 있는 초기 5개 화면 지시문 전체입니다.** Figma Make에 실제 입력한 모든 문장이 동일했다고 단정하지 않습니다.

```text
이벤트 기반 사진 공유 앱 "phoU"의 모바일 화면 5개를 만들어줘.

[첨부 이미지 사용법]
- 손그림 스케치: 화면 구성과 레이아웃 기준
- 레퍼런스 앱 이미지: 색·형태·분위기만 참고. 레이아웃은 그대로 베끼지 말고 스케치를 따를 것

━━━━━━━━━━━━━━━━━━
[서비스]
여행·모임·축제에서 친구들 폰에 흩어진 사진을 이벤트 단위로 모아,
AI가 정리·선별을 도와 빠르게 공유하는 앱.
핵심: 이벤트 기간을 정하면 그 시간에 찍은 사진을 자동으로 찾아와 공유 후보로 보여준다.

[사용자]
친구들과 이벤트에서 사진을 많이 찍는 20~30대.
이번 화면들은 "앨범을 만들어 친구들에게 공유하는 사람" 흐름.

━━━━━━━━━━━━━━━━━━
[디자인 시스템 — 5개 화면 모두 동일하게 적용]
전체 무드: 흑백 미니멀. 색은 거의 쓰지 않고 사진이 유일한 컬러가 되게.

색상 (이 값만 사용, 유채색 추가 금지)
- 배경: #FFFFFF
- 보조 배경(카드·입력창·비선택 칩): #F2F3F5
- 테두리·구분선: #E6E7EA
- 본문 텍스트·강조(메인 버튼, 선택 칩, 토글 ON): #111111
- 보조 텍스트: #8E8E93
- 비활성: #C7C7CC
- 그라데이션 금지

형태
- 버튼·칩·검색창·하단 탭: 완전히 둥근 알약(pill) 모양
- 사진 카드 모서리 24px, 일반 카드·입력창 20px
- 선택된 칩: 검정 배경 + 흰 글씨 / 선택 안 된 칩: #F2F3F5 배경 + 회색 글씨
- 토글: ON은 검정, OFF는 #E6E7EA
- 메인 버튼: 검정 배경 + 흰 글씨, 높이 56px, 알약 모양, 화면 하단 고정, 좌우 여백 20px
- 비활성 버튼: #C7C7CC 배경
- 그림자: 아주 약하고 넓게 (떠 있는 느낌만)

사진 위 정보 표시
- 사진 카드 하단에 반투명 블러 박스(유리 느낌)를 깔고 그 위에 흰 글씨
- 밝은 사진에서도 글씨가 읽히도록 블러 박스를 충분히 어둡게

하단 탭
- 화면 하단에서 살짝 떠 있는 둥근 알약형 탭 바
- 선택된 탭 아이콘만 진하게, 나머지는 회색

타이포 (Pretendard)
- 화면 제목 26px Bold
- 섹션 제목 18px SemiBold
- 본문 15px Regular
- 보조 설명 13px Regular

레이아웃
- 화면 390×844, 좌우 여백 20px, 간격은 8의 배수(8/16/24/32)
- 아이콘: 얇은 선 스타일로 통일, 이모지 금지
- 여백 넉넉하게, 한 화면에 정보 많이 넣지 않기

문구
- 짧고 자연스러운 한국어 존댓말 ("~해요" 체)

━━━━━━━━━━━━━━━━━━
[만들 화면 — 이 5개만, 버튼으로 서로 연결]

1. 홈
- 상단: "오늘도, 좋은 순간 함께해요" 인사 + 오른쪽 알림 아이콘·프로필 사진
- 칩 필터: 전체 / 진행 중 / 지난 앨범 (전체 선택 상태)
- "내 그룹" 섹션: 공유 폴더 사진 카드 (대표 사진 크게,
  하단 블러 박스에 폴더 이름 · 날짜 · 참여자 수)
  예시: 제주도 여행(2026.10.03~10.05 · 4명) / 동아리 MT(2026.11.12~11.13 · 11명) / 강릉 가족여행(2026.09.14 · 5명)
- 떠 있는 하단 탭: 홈 / 전체 사진 / + 새 그룹(가운데, 검정 원형 버튼) / 내 사진 / 설정
- 빈 상태: 폴더가 없으면 "새 공유 폴더를 만들어볼까요?" + "폴더 만들기" 버튼
- "+ 새 그룹" 누르면 → 2번 화면

2. 이벤트 폴더 만들기
- 상단: 뒤로가기(원형 버튼) + "이벤트 폴더 만들기" + 보조 설명 "함께 찍은 순간을 한 곳에 모아요"
- 폴더 이름 입력 (placeholder: 예) 동아리 MT, 제주도 여행 / 0/20 글자수)
- 이벤트 기간: 시작 날짜·시간 ~ 종료 날짜·시간
- 장소 (선택): 예) 제주도, 홍대
- "기간 내 찍은 사진 자동 공유" 토글 + 설명 "이벤트 기간에 촬영한 사진을 자동으로 불러와요"
- 하단 버튼 "다음" → 3번 화면 (폴더 이름이 비어 있으면 비활성)

3. 사진 공유 옵션 설정
- 상단: 뒤로가기 + "어떤 사진을 공유할까요?" + 보조 설명 "자동으로 불러올 때 제외할 사진을 골라요"
- 토글 카드 5개 (왼쪽 선 아이콘 + 이름 + 오른쪽 토글):
  나만 나온 사진 제외 / 흐릿한 사진 제외 / 비슷한 사진은 대표사진만 / 스크린샷 제외 / 영상 제외
- 그 아래 알약형 보조 버튼: "고르기 어려우면 AI에게 맡기기"
- 하단 버튼 "다음" → 4번 화면

4. 이벤트 기간 사진 불러오기
- 먼저 로딩 상태: "이벤트 기간 사진을 찾고 있어요" + 진행 표시 (2초 후 결과로 전환)
- 결과 상단: "사진 86장을 찾았어요" (큰 제목)
  + 보조 설명 "옵션에 따라 12장을 제외했어요"
  + 칩: 흐릿함 5 · 스크린샷 4 · 영상 3
- 사진 그리드 3열, 모서리 둥근 사진, 각 사진 오른쪽 위 체크 표시 (탭하면 선택 해제)
- "제외된 사진 보기" 텍스트 링크
- 하단 버튼 "사진 74장 공유하기" (선택 수에 따라 숫자 변경) → 5번 화면
- 빈 상태: "아직 이 시간대에 찍은 사진이 없어요" + "직접 추가하기" 버튼
- 사진 접근 거부 상태: "사진 접근을 허용하면 자동으로 불러올 수 있어요" + "직접 고르기" 버튼

5. 링크·QR 보내기
- 상단: "앨범이 만들어졌어요" + 보조 설명 "친구들을 초대해 사진을 함께 모아요"
- 큰 QR 코드 카드 (흰 카드, 둥근 모서리, 약한 그림자)
- 공유 링크 입력창 형태 + 오른쪽 "복사" 알약 버튼 (누르면 하단에 "링크를 복사했어요" 토스트)
- "다른 방법으로 공유": 카카오톡 / 인스타그램 / 더보기 (원형 아이콘 버튼)
- 링크 유효기간: "2026.12.01까지 유효해요" + "변경" 텍스트 버튼
- 하단 버튼 "완료" → 1번 홈 (새 폴더 카드가 맨 앞에 추가된 상태)

━━━━━━━━━━━━━━━━━━
[사진 이미지]
- 여행·풍경·음식·단체 분위기의 플레이스홀더 이미지 사용
```

### 02. 결과를 확인하며 수정 요청

**원문 발췌 — 버튼의 의미**

> 1번의 전체를 누르면 2번 전체로 가는게 좀 어색하지않나? 베스트컷의 모음을 전체보는거아냐 ?

| 후속 요청 요약 | 판단 기준 | 반영한 결과 |
| :--- | :--- | :--- |
| 추천이 사람의 눈에도 좋은 사진일까? | 단정적 표현보다 근거·직접 선택이 필요 | ‘베스트’ → ‘AI 추천’, 이유와 선택 표시 |
| 비슷한 사진인데 안 비슷하고, 장면별과 겹친다 | 분류의 역할과 비교 사진이 맞아야 함 | 대표 비교로 통합, 샘플 변형 표시 |
| 선택하지 않았는데 왜 정해진 장수를 저장하나? | 저장 범위는 사용자 선택과 일치해야 함 | 체크·장수 연결, 추천 전체선택 삭제 |
| 뒤로가면 홈으로 가거나 맨 위로 올라간다 | 이전 탐색 맥락을 유지해야 함 | 상세 복귀·홈/앨범 스크롤 복원 |
| 위·아래 ‘내 사진’은 같은 기능인가? | 업로더와 등장 인물을 구분해야 함 | ‘내가 올린 사진’ / ‘내가 나온 사진’ 분리 |

*표는 대화의 요청을 정리한 요약이며, 새로 작성한 프롬프트를 당시 원문인 것처럼 제시하지 않습니다.*
